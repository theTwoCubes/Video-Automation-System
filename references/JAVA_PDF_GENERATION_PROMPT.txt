```latex
\section{ArrayList \& LinkedList}

Both \java{ArrayList} and \java{LinkedList} implement the \javatype{List} interface from \javapkg{java.util}, but their internal structures produce completely different performance characteristics.
\java{ArrayList} is backed by an \java{Object[]} array, so random access via \java{get(i)} is O(1).
\java{LinkedList} stores each element in a \java{Node} object holding a value and two pointers -- so \java{get(i)} walks the chain and costs O(n).
The catch is that 100\% of developers reach for \java{LinkedList} thinking it will be faster for insertions, and they are usually wrong because cache misses from pointer chasing dominate.

\begin{javacode}
import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;

public class ListComparison {
    public static void main(String[] args) {
        List<Integer> arrayList = new ArrayList<>();
        List<Integer> linkedList = new LinkedList<>();

        for (int i = 0; i < 1_000_000; i++) {
            arrayList.add(i);
            linkedList.add(i);
        }

        // O(1): direct index calculation into backing array
        System.out.println(arrayList.get(500_000));  // 500000

        // O(n): walks 500000 nodes
        System.out.println(linkedList.get(500_000)); // 500000 - same result, very different cost
    }
}
\end{javacode}

The common mistake is using \java{LinkedList} as a \javatype{Queue}.
Use \java{ArrayDeque} instead: it is faster than \java{LinkedList} for all deque operations because it uses a circular buffer rather than pointer-linked nodes.
Notice how every \java{_} underscore in class names like \java{ArrayDeque} is safely inside the \java{} macro and NOT written raw in the surrounding prose!
```
