Objective:
==================================================================

Write a complete handbook covering the subject from absolute beginner level to advanced professional topics.
The handbook should be sufficiently complete that another LLM can generate an entire university-level course using only this document.
Approximate size:

80–100 dense pages of technical content.

If additional pages are required for completeness, prefer completeness over brevity.

==================================================================
DOCUMENT STRUCTURE
==================================================================

Use the following LaTeX structure exactly.
The document must begin with:

```latex
\begin{document}

\tableofcontents
```

Do not place any content before the table of contents.
Use only numbered headings.
Allowed hierarchy:

- \chapter{}
- \section{}
- \subsection{}
- \subsubsection{}

Never use:
- \chapter*
- \section*
- \subsection*
- \paragraph
- \subparagraph

Maximum heading depth is:

\subsubsection

Section numbering must be sequential.
Never skip numbers.

Example:
1
1.1
1.2
1.2.1
1.2.2
1.3

Do not manually create a table of contents.
LaTeX must generate it automatically.
Each section must be self-contained.
A reader opening directly to Section 7.5 should understand the concept without reading previous sections, except for explicit references such as:

"See Section 3.2."

Every section should cover exactly one major concept.

If a section exceeds approximately 800 words, split it into subsections.

==================================================================
CONTENT REQUIREMENTS
==================================================================

The handbook must be exhaustive.
Do not intentionally omit advanced topics.
Do not skip concepts because they are uncommon.
If a topic belongs in a complete education on the subject, include it.
Organize chapters in a logical learning progression.
Each chapter should naturally build upon earlier chapters.

Each chapter should contain:
- Introduction
- Core explanation
- Syntax (when applicable)
- Internal working
- Practical examples
- Common mistakes
- Best practices
- Notes where appropriate

Prefer textbook-style prose over large bullet lists.
Avoid shallow summaries.
Explain concepts thoroughly.

==================================================================
PEDAGOGICAL REQUIREMENTS
==================================================================

Whenever introducing a concept, explain:

1. What it is.
2. Why it exists.
3. The problem it solves.
4. How it works.
5. When to use it.
6. When not to use it.
7. Common mistakes.
8. Best practices.

Do not merely define concepts.

Teach them.

Assume the reader starts with no prior knowledge.
Gradually progress toward expert-level material.
When introducing advanced topics, connect them to previously introduced concepts.
Explain design decisions whenever appropriate.
Historical context should only be included when it improves understanding.

==================================================================
CODE EXAMPLES
==================================================================

Every important concept should include practical examples.

Examples must:
- compile or execute correctly
- use modern best practices
- be realistic
- increase gradually in complexity
- explain why the code works
- demonstrate both correct and incorrect usage whenever appropriate

All code must use LaTeX lstlisting.

Example:

```latex
\begin{lstlisting}[language=<LANGUAGE>, caption={Example}]
...
\end{lstlisting}
```

Never place long code inline.

==================================================================
WRITING STYLE

Write like an experienced professor writing a university textbook.

Do not sound like an AI.

- em dashes
- marketing language
- motivational writing
- conversational filler
- unnecessary enthusiasm
- repetitive transitions
- "Let's dive in"
- "In this guide..."
- "As an AI..."

Use clear technical English.

Prefer precise explanations over flowery writing.

Dense information is preferred.
